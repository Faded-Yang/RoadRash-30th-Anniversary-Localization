## 跨代码页渲染修复

### 修复了什么
旧版把所有非中文语言装到中文 Windows 上会**满屏问号**（例如 #49 语言、日语缺字）。根因是 1996 年的 ANSI 架构：
`LoadStringA` 会按**系统 ANSI 代码页**把 UTF-16 转字节，中文系统（CP936）下其他语言的字符直接变 `?`。

### 怎么修的
在 EXE 的代码洞里加了 **120 字节的「文本转码兼容层」**：把 6 处 `LoadStringA` 调用改为
`LoadStringW` + `WideCharToMultiByte(目标代码页)`，绕开系统代码页。

| 项目 | 变化 |
|---|---|
| 桩代码 | 120 字节，0 重定位，放在 .text 既有对齐填充里 |
| 改动 | 关 ASLR、.text 加写权限、6 处调用点改为 `call` 桩 |
| 效果 | **63 种语言中的任意一种，在任何语言的 Windows 上都能正确渲染** |

### 验证
- 韩文（CP949）在中文 Windows（CP936）上完整显示 —— 韩文完全不在 GBK 里，是「真的绕开了系统代码页」的铁证
- 日文、阿拉伯文、俄文等同样不再依赖系统区域设置

### 安装体验
- **必须把安装器放进游戏目录**（与 `RoadRash95.exe` 同级）再双击，不再自动猜测路径
- 卸载仍是运行后选 `uninstall`，完整还原

### 说明
- 仍然只有 Windows 存在 ANSI 代码页的书写系统可渲染（印地语、泰米尔语、高棉语等 30+ 种依旧做不到）
- 简体中文为人工翻译 + 官方四语逐条校审，其余为机器翻译
